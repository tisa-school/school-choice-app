# Capacitor mobile app: setup and release guide

## What was preserved

Branch: `feature/capacitor-mobile`, based on main `59674ca`. The actual repository is Django 5.2 with server-rendered HTML; it has no Next.js server to export. Existing routes, Vercel deployment, Neon database, administrator photo uploads and demo state code remain in place. No production migration or live deployment was performed.

The app uses a **local bundled frontend**, not a remote website iframe or Capacitor `server.url`. Shared Django discovery, visibility, saving, participation, ticketing, notifications and calendar services remain authoritative. The additive API at `/mobile/v1/` is disabled unless `MOBILE_API_ENABLED=1`.

Native app screens: Home, activity filters/details, school discovery/shortlisting, saved events and schools, parent profiles/participation decisions, family plans/calendar, inbox, announcements, sign-in, parent signup, profile, push preferences and deletion requests. Public discovery works without signing in. Real account operations retain authentication and parental password checks.

Complex existing tools (organiser/staff management, photo management, collections, AI Finder, detailed school comparison and calendar editing) open the **existing HTTPS website in the system browser**. They may require a separate website sign-in. No native token is put in a URL or given to that browser. Existing features are preserved this way; they have not all been rebuilt as native screens.

## 1. Get the isolated branch

```bash
git clone https://github.com/tisa-school/school-choice-app.git
cd school-choice-app
git switch feature/capacitor-mobile
```

Do not merge to main or change production settings until the owner approves. A Vercel Preview may be generated by GitHub integration, but it is not proof of functionality. Use a separate preview database. The existing build script does not migrate preview databases automatically.

## 2. Prepare a backend for testing

Python 3.12 and the existing Python dependencies are required. For local testing, use a separate SQLite database (default development configuration); never paste production database credentials into a terminal command or the mobile project.

```bash
python3.12 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
MOBILE_API_ENABLED=1 MOBILE_ALLOWED_ORIGINS=http://127.0.0.1:5173 python manage.py runserver 127.0.0.1:8765
```

These migration instructions are for **your isolated development database only**. Native devices require an approved reachable HTTPS backend. On a separate approved Vercel Preview, configure its existing Django secret, separate Neon database and email configuration, then add `MOBILE_API_ENABLED=1`. Run migrations against that preview database through your trusted backend workflow. Native origins default to `capacitor://localhost,https://localhost`. Keep the existing website CSRF/cookie protection; do not disable it globally or allow arbitrary CORS origins.

Do not put `DATABASE_URL`, `DJANGO_SECRET_KEY`, `ANTHROPIC_API_KEY`, APNs signing keys or Firebase service-account credentials in a `VITE_` variable. All Vite variables are public.

## 3. Install and build the mobile frontend

Install Node 24 LTS (Node 22+ required). From a second terminal:

```bash
cd school-choice-app/mobile
npm ci
cp .env.example .env.local
```

For browser-only local development, set:

```dotenv
VITE_API_BASE_URL=http://127.0.0.1:8765
```

Then:

```bash
npm run dev
```

Open `http://127.0.0.1:5173`. The browser preview keeps authentication **in memory only**, intentionally. Reloading the browser requires signing in again; saved data is still in the database. Native sessions restore through Keychain/Keystore. Existing website demo persistence remains unchanged.

For a native build, replace the URL with your approved **HTTPS** preview origin, without a path, credentials, query or trailing API segment:

```dotenv
VITE_API_BASE_URL=https://YOUR-APPROVED-PREVIEW.vercel.app
```

```bash
npm run build
npm test
npx cap sync
```

The generated iOS and Android projects are committed already. Do not run `cap add` again. Re-run build and sync whenever frontend code or the public backend origin changes. Existing production currently lacks the opt-in API until separately approved deployment; the app displays a clear connection/configuration error in that case. Do not enable cleartext HTTP for release.

## 4. Android Studio

Install Android Studio, Android SDK Platform 36/build tools, JDK 21, and an Android 7/API24+ device or emulator. Configure Android Studio's Gradle JDK and SDK path on your machine.

```bash
cd mobile
npm run build
npx cap sync android
npx cap open android
```

Select the `app` configuration and Run. CLI alternative once SDK/JDK are available:

```bash
cd android
./gradlew assembleDebug
# Windows: gradlew.bat assembleDebug
```

Debug APK: `app/build/outputs/apk/debug/app-debug.apk`. Release signing requires your own upload key and Play developer account. Never commit keystores, passwords or signing configuration containing secrets. Confirm the application ID before creating the Play listing.

The custom calendar adapter opens the installed calendar editor with prefilled dates. It never reads the calendar and does not claim the user saved the event. Android backup is disabled; session ciphertext is encrypted using an Android Keystore key. Screenshot capture is disabled for private-screen protection; assess presentation needs on actual devices rather than removing protection globally.

## 5. Xcode on a Mac

Install a current Xcode supporting Capacitor 8 and iOS 15+, its command-line tools and an iOS simulator/device. Swift Package Manager is configured; CocoaPods is not required.

```bash
cd mobile
npm ci
npm run build
npx cap sync ios
npx cap open ios
```

In Xcode open the `App` target, choose Signing & Capabilities, select your development team, verify `org.unicornschool.tkzone`, choose an iPhone and Run. Resolve Swift packages if prompted. The configured scheme is `App`. Never embed Apple signing credentials in Git.

Custom plugins are registered by `TKBridgeViewController` and included in the Sources build phase. Keychain stores the session with `AfterFirstUnlockThisDeviceOnly`. Calendar uses EventKit's native review editor, requesting write-only access on iOS17+ and legacy calendar permission on iOS15/16. Permission explanations are in Info.plist. Test grant, denial, cancellation and save on a device.

## 6. Icons, splash and links

A TK monogram icon and purple splash assets are included. Original fonts and their licences are bundled. The activity hero is an existing illustrative AI image and is explicitly labelled as such.

Regenerate assets after editing `mobile/resources/icon.svg` and rendering it to `icon-only.png`:

```bash
cd mobile
npx capacitor-assets generate --assetPath resources --ios --android --iconBackgroundColor '#440CB0' --iconBackgroundColorDark '#440CB0' --splashBackgroundColor '#440CB0' --splashBackgroundColorDark '#440CB0'
npm run sync
```

Custom links use `org.unicornschool.tkzone://open?path=/events/123/` with a strict route allowlist. These are navigation only, never sign-in links. Verified universal/app links require domain association and signing fingerprints and are not configured yet.

## 7. Optional push: owner credentials required

No push was sent during implementation. In-app inbox works independently. Registration is explicit opt-in for parents or verified adult staff/organisers. Children cannot register devices through the API. Registration is removed on logout/deletion request. No child name, activity title or private message goes on the lock screen.

Android: create a Firebase project matching the application ID, download `google-services.json` to `mobile/android/app/` (ignored by Git). Enable FCM. Keep the Firebase service-account JSON **only on the server**, as a secret `MOBILE_FCM_CREDENTIALS_JSON`, or reference a securely mounted `MOBILE_FCM_CREDENTIALS_FILE`. Do not confuse client Firebase configuration with the private service-account key.

iOS: enable Push Notifications capability for the App target in Xcode and use a matching provisioning profile. Xcode must generate/sign the APNs entitlement. Create an APNs authentication key through your Apple developer account. Configure server secrets `MOBILE_APNS_PRIVATE_KEY` (multiline .p8 contents), `MOBILE_APNS_KEY_ID`, `MOBILE_APNS_TEAM_ID`; alternatively use a secure `MOBILE_APNS_KEY_FILE`. `MOBILE_APNS_SANDBOX=1` is development; production signing requires `0`. These secrets never belong in the iOS project. No Apple team, entitlement signing or private key is supplied here.

Install server-side delivery dependencies **only after reviewing and configuring the optional integration**:

```bash
pip install -r requirements-mobile-push.txt
```

On Vercel they must also be included in the backend dependency installation before using delivery. The adapter uses HTTP/2 APNs and FCM HTTP v1. A trusted operator can test one **owned test notification/device**:

```bash
python manage.py send_mobile_push --notification-id YOUR_TEST_NOTIFICATION_ID
```

Provider acceptance is not device receipt. This command has no automatic retries and repeating it can duplicate pushes. Automatic background delivery/queueing is not configured; choose and test an idempotent background job before calling push production-ready. Capabilities indicate supplied configuration, not validated credits, credential validity or successful delivery. Actual push receipt has not been tested.

## 8. Security, privacy and parental controls

- All new personal endpoints require expiring, revocable bearer sessions. Only a SHA-256 token hash is stored server-side. Website cookies do not grant API access.
- Child data is scoped to the authenticated parent's account. Existing school visibility and staff authorisation remain authoritative. No demo role switch grants access to these APIs.
- Parent permission requires the real parent password and remains separate from organiser admission. A family plan is not a booking.
- Tokens are never stored in localStorage, logs, Git, analytics or deep-link URLs. Public frontend build configuration contains only a backend origin.
- No real data is seeded for app demonstrations. Tests use a disposable database. No private messaging, contacts/location access, tracking or advertising SDK was added.
- A deletion request requires a password, immediately revokes mobile sessions/removes registrations, and appears in a read-only superuser review queue at `/admin/`. It **does not automatically delete the account**. A documented operational deletion/retention workflow, including protected organiser records and private media, must be agreed and tested before store submission. Do not mark this requirement complete merely because the request returns 202.
- Review the existing hosted privacy policy, support contact, child-photo permissions, parental consent, GDPR/children's privacy requirements and store Families/Kids restrictions with the responsible adults. No certification or legal compliance claim is made by this change.
- Prepare truthful Apple App Privacy / Google Data Safety declarations for account data, children’s private profiles, uploads, participation, notification tokens and provider processing. Supply store reviewers a safe test account and explain role-based access.

## 9. Validation commands and current limits

```bash
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py test community --noinput
python manage.py test community.browser_mobile --noinput
cd mobile
npm ci
npm run build
npm test
npx cap sync
```

The browser test requires Playwright, Chromium and permission to bind local ports. Run Django database suites sequentially. In this environment Chromium is `/usr/bin/chromium`; adapt the test executable path on your machine.

Executed successfully: Django checks; no pending migration changes; 317 Django tests including 18 mobile API tests; TypeScript + production web build; 5 mobile security tests; Capacitor sync for both projects; one Chromium parent workflow at 390px (filters, save, request, password approval and family plan). Real screenshots: `artifacts/mobile/`.

Not verified: native Swift/Java compilation, native secure storage restore, device calendar editor, APNs/FCM receipt, signing, store review, remote preview API or production deployment. Android Gradle download was blocked by environment networking; Xcode is unavailable on this Linux machine. Native projects need actual Mac/Android Studio validation before distribution. This is development preparation, not an App Store-ready release.

## 10. Release boundaries

Keep this branch separate. Review the PR, use an isolated approved preview database, run the checks above and complete device/signing/privacy work. Only then request approval to merge and enable the mobile backend on production. Do not change the existing live website simply to test the app. Vercel hosts the backend; it does not build/sign an IPA or AAB. Expo EAS commands are unnecessary for this Capacitor project.
